# 출시와 후속 버전 검토

## 관계가 바뀔 때

| 상황 | 현재 제품 기준 | 검증 기준 |
| --- | --- | --- |
| 한쪽이 연결을 끊음 | 양쪽의 활성 연결을 닫는다. 과거 공동 여행, 사진, 댓글은 지난 기록에서 읽는다. 새 쓰기와 이전 관계의 비교는 중단된다. | 두 계정에서 아카이브 읽기와 쓰기 거부, 상대 화면 갱신을 확인한다. |
| 같은 사람과 다시 연결 | 새 초대를 두 사람이 사용한다. 새 커플 ID, 새 기준일, 새 비교 승인으로 시작한다. 이전 여행, 사진, 대표 사진은 지난 기록에 남는다. | 예전 승인과 새 커플의 교집합이 섞이지 않고, 이전 앨범이 새 지도에 표시되지 않는지 확인한다. |
| 다른 사람과 연결 | 이전 상대에게 새 거주지나 활성 커플 키를 전송하지 않는다. | 두 관계에서 사용자 필드의 접근이 분리되는지 확인한다. |
| 계정 삭제 요청 | 기존 활성 커플이 아카이브된다. 요청자의 사진 날짜·지역 집계를 즉시 정리한다. 유예 중 상대는 지난 기록을 읽을 수 있다. | 삭제 요청 직전의 스캔, 중복 요청, 취소, 상대 앱 복귀를 확인한다. |
| 유예 중 취소 | 계정은 유지된다. 새 초대로 관계를 다시 맺을 수 있다. | 취소 전후 사용자 ID가 같고 이전 관계가 읽기 전용인지, 다른 기기에서 스캔이 다시 열리는지 확인한다. |
| 30일 만료와 정리 | 대상 커플의 검증된 Storage 객체, 공동 기록, 탈퇴 계정 순서로 정리한다. 실패 단계부터 다시 시도한다. 상대 계정은 유지된다. | 시험 프로젝트에서 저장소 삭제 실패, 이미 지운 파일, Auth 삭제 실패, 중복 실행과 재시도를 확인한다. |

지난 기록에서 기기로 저장하는 기능이 출시 범위에 들어갈 때는 기존 열람 권한을 그대로 확인한다. 계정 삭제로 공동 기록이 사라질 수 있다는 안내를 내보내기 흐름에도 제공한다. 관계를 다시 맺었을 때 과거와 새 기록을 합치는 기능은 두 사람의 명시적 선택, 중복·권한·구독 범위의 설계가 필요한 후속 기능이다.

## 기기와 서버의 역할

| 기기 | 서버 |
| --- | --- |
| 사진 권한 요청, 원본의 위치로 지역 판정, 혼자일 때 미리보기, 선택한 사진 인코딩과 EXIF 검사, 계정별 사진첩 스캔 캐시 | 초대와 커플 상태, 기준일, 합산 비교 승인, 공동 여행·사진·댓글 및 지난 기록, 탈퇴 유예와 정리 |
| 비교가 가능한 기간의 날짜·조각 코드·장수만 동기화한다. 업로드는 사용자가 고른 사진에 한한다. | 개인 집계는 본인 전용이다. 두 사람의 승인 범위가 겹치는 기록만 상대에게 공개한다. 사진은 비공개 저장소에서 서명 URL로 읽는다. |

## 버전과 수익화 제안

| 버전 | 제품 범위 | 출시 판단 |
| --- | --- | --- |
| **1.0** | 커플 연결, 지도, 선택 업로드, 비교 승인, 지난 기록, 탈퇴를 무료로 제공한다. | Apple 로그인과 삭제 토큰 철회, 공개 개인정보 처리방침, 콘텐츠 신고 대응, 정리 작업과 두 기기 검증을 완료한다. |
| **1.1** | 일회성 테마 또는 기념일 지도 PDF·고해상도 이미지 꾸미기부터 시험한다. 기본 기록 열람과 개인정보 관련 내보내기는 무료로 둔다. | 결제 복원, 환불, 무료 흐름 이탈과 유료 꾸미기 사용률을 확인한다. |
| **1.2 이후** | 사진 저장 용량 추가, 고화질 보관처럼 지속 비용과 가치가 있는 기능에 한해 구독을 검토한다. | 활성 커플당 저장량·전송량, 무료 한도 도달률, 정리 지연과 월간 유지율을 집계한 뒤 가격과 한도를 정한다. 원본 사진·날짜별 위치 기록은 지표에 사용하지 않는다. |
| **2.x** | Android와 정산을 순차 출시한다. 원본 메타데이터·백업·사진 권한을 플랫폼별로 검증한다. | Android OAuth와 서명, HEIC/JPEG, 사진 접근과 결제 복원, iOS·Android에서 같은 계정으로 로그인하는 흐름을 완료한다. |

구매 권리는 결제한 **개인 계정**에 귀속하고, 공동 혜택은 그 사람의 활성 커플 한 곳에 적용하는 모델을 권장한다. 연결 해제나 상대 탈퇴로 결제 권리가 상대에게 넘어가지 않는다. 구독이 만료되면 신규 유료 업로드나 확장을 제한하고 기존 기록 열람과 내보내기는 유지한다. 같은 두 사람이 재결합해도 유료 저장 한도만 새 활성 커플에 적용할 수 있고, 지난 앨범이나 비교 승인은 이전하지 않는다.

앱 계정 삭제와 스토어 구독 해지는 별개이므로 삭제 안내에 관리 링크와 갱신 상태를 표시한다. 향후 구독을 도입하면 서버가 스토어 검증 결과를 멱등하게 반영하고, 복원·해지·환불과 계정 삭제 후 재가입을 각각 검증한다. 거래와 권한 확인에 필요한 최소 필드의 보유 기간은 출시 모드에서 따로 결정한다.

디지털 기능은 기본적으로 플랫폼 결제를 적용한다. 한국의 대체 결제는 별도 조건이 있어, 도입 시점에 다시 검토한다. ## 출시 환경 확인

- 연결 대기 중 합류 신호가 누락되면 앱이 전면에 있고 초대가 유효한 동안 최대 15초 간격으로 현재 관계만 보완 조회한다.

- 출시 프로젝트에서 개발용 단독 연결 RPC가 없어야 한다. Apple과 카카오 제공자, 이메일 가입 정책, OAuth 리다이렉트 정책을 확인한다.
- 새 앱보다 먼저 DB 마이그레이션을 적용하고 현재 관계·아카이브 RPC의 동작을 확인한다. 구버전 앱은 기존 관계 정보에서 상대 이름과 삭제 배너 일부가 생략될 수 있으므로 업데이트된 앱으로 전환한다. 사진 삭제 경계를 확인한 다음 정리 함수를 올린다. 스케줄 등록만으로 완료 처리하지 않고 실제 한 차례 성공 응답, 다음 재시도 및 실패 알림을 확인한다.
- 오래된 사진 날짜·지역을 갖는 앱 백업, 구형 iPhone의 과열·메모리, iCloud 미리 받기, VoiceOver 조각 선택, 실제 두 대의 상대 갱신을 확인한다.
- 승인 전 사진 집계를 서버에 보관해야 하는지 다음 기준 문서에서 판단한다. 승인만 서버에 보관하면 개인정보와 요청량을 줄일 수 있고, 새 기기에서 미승인 기록을 자동 복구하는 범위는 줄어든다.
