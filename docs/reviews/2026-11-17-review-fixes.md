# 코드 리뷰 보완

이 문서는 공개 가능한 변경 사항과 검증을 기록한다. 내부 제품 설계·계획은 gitignore 정책대로 공개하지 않는다.

## 결정

사용자는 날짜·지역별로 비교를 승인한 기록만 상대와 대조하는 방식을 선택했다. 최초 승인 목록은 비어 있고, 새 커플로 승인 범위를 승계하지 않는다. 비승인 원본은 교집합 RPC에서 사용하지 않는다. 승인한 날짜·지역은 상대가 알아낼 수 있다는 안내를 표시한다.

## 범위

기존 Flutter·Riverpod·Supabase 구조와 의존성을 유지한다. 운영 DB 변경·배포·PR 병합은 포함하지 않는다. 시각 디자인 개편은 제안으로 남긴다.

## 검증 기록

- 기준 상태: Flutter 테스트 118개, dart analyze 통과.
- 공유 승인: 미승인 기본값·단독 승인·원본 없는 승인·사귄 날 이전·상대 조회·조작 입력·철회·원본 삭제·커플 불일치·아카이브·RLS를 포함한 pgTAP 13개 통과.
- UI: 기본 미선택·기존 승인 복원·저장 실패 선택 유지와 재시도 확인.
- 동기화: 사용자·커플 변경 및 삭제 후 무효화 회귀 통과.
- 저장소 초기 상태: 원격 브랜치가 없어 사용자가 2026-11-18에 초기 main 게시와 PR 생성을 승인했다. 현재 공개 소스만 담은 부모 없는 초기 커밋을 기준으로 삼고, 내부 문서를 포함했던 로컬 과거 이력은 공개하지 않는다.

## 캐시와 동기화

상대의 비교 승인 행은 본인 전용 RLS이므로 상대 클라이언트에 그대로 발행하지 않는다. 앱 복귀와 재연결 시 교집합을 다시 읽고, 결과가 없을 때 지도 안내의 ‘함께 간 기록 새로 확인’으로 즉시 다시 조회할 수 있다. 승인 목록 자체를 상대에게 통지하는 채널은 추가하지 않는다.

- 통합 2차 Flutter 테스트 132개 통과, 로컬 pgTAP 135개 통과, 초대 동시 수락에서 성공 1건·커플 1개 확인.
- Edge Function 실제 엔트리포인트를 외부 API 대체 환경에서 실행해 무권한 거부, 삭제 순서, Storage 실패 중단, Auth 실패 전파 4개 테스트 통과(Node 26). 실제 클라우드 배포는 수행하지 않았다.
- 공유 선택 화면은 재조회 로딩 중 이전 기록을 숨기는 회귀를 추가했다.

## 독립 리뷰 반영

- 공유 승인 화면의 로딩뿐 아니라 오류 응답에도 이전 값을 숨기도록 했다. 회귀 위젯 테스트로 확인했다.
- 계정별 아카이브·사진·초대·로그인 신원·삭제일은 사용자 ID를 키로 하는 provider family로 분리했다. 사진 URL FutureBuilder도 사용자 키를 가지며, 사진 확대 화면은 계정 변경 시 이전 사진을 숨긴다.
- 실제 로컬 Realtime 통합 테스트로 연결 대기 중 상대 합류와 사진 INSERT·DELETE 이벤트 도달을 확인했다. SQL의 REPLICA IDENTITY FULL도 테스트로 고정했다.
- 앱의 설정에서 사귄 날 수정 경로, 전체 스캔 성공·실패, 실패 사진의 선택 변경 후 재시도를 테스트했다.

## 의도한 동작

승인을 철회해도 이미 확인한 여행은 지우지 않는다. 사진첩에서 사진을 지워도 확인된 여행을 유지한다는 기존 원칙을 따른다. 승인해 공개된 날짜·지역을 상대방의 기억이나 별도 저장본에서 회수할 수는 없다.

## 게시 전 재검증

2026-11-18 전체 실행에서 일반 테스트 140개는 통과했으나 Realtime 통합 1개가 10초 시간 초과로 실패했다. 같은 시점의 로컬 서버 로그에 테넌트 초기화가 기록됐으며, 코드를 바꾸지 않은 단독 재실행은 통과했다. 초기화 지연과의 인과관계는 확정하지 않았다. 게시 전 전체 재실행은 141개 모두 통과했고 정적 분석도 통과했다.

## PR 재검토 보완

- 비교 범위 저장은 사용자·커플 단위로 직렬화한다. 두 저장을 겹쳐 실행해 마지막 요청의 목록만 남는지 확인한다.
- 만료 계정 하나의 정리가 실패해도 다른 계정과 고아 파일, 만료 초대를 정리한다. 실패한 계정은 다음 실행에서 다시 처리한다.
- 최신 비교 결과에서 빠진 미확정 후보는 열린 화면에서도 제거하고, 삭제 취소가 거부되면 그 사실을 알린다.
- 사진 재시도는 같은 업로드 ID를 사용한다. 서버 저장 결과가 불확실하면 사진 파일을 보존한다.
- Realtime 통합 테스트는 PostgreSQL 변경 구독이 준비됐다는 시스템 메시지를 받은 뒤 사진을 추가한다. 실패할 경우 구독 준비, 사진 추가, 사진 삭제 중 어느 단계에서 시간이 초과됐는지 표시한다. [Supabase Realtime 프로토콜](https://supabase.com/docs/guides/realtime/protocol#system)

재검토 검증은 Flutter 146개, 로컬 pgTAP 135개, 정리 함수 7개가 통과했고 정적 분석에 문제가 없었다. 초대 수락과 비교 승인 동시 실행 테스트도 통과했다. 사진 재시도는 로컬 Storage에서 같은 ID로 다시 저장하는 경로와 Storage·DB 응답을 잃는 모의 실행을 각각 검증했다.

## c30012a 재리뷰

- 로컬 Realtime v2.103.2에서 `REPLICA IDENTITY FULL`일 때 `couple_id` 필터를 건 사진 DELETE가 도착했다. 해당 커플 소속이 아닌 계정도 필터 없는 구독과 같은 커플 ID를 필터로 지정한 구독에서 DELETE를 받았다. 세 사진 구독의 이전 값에는 사진 ID만 있었고 지역 코드와 촬영 시각은 없었다. 생활권 수정 테이블은 조각 코드가 기본 키에 속하므로 사진에서 확인한 열 구성을 다른 테이블에 일반화할 수 없다. 변경 후에는 사진·여행 등을 원본 행 발행에서 제외하고 비공개 Broadcast의 조회 신호로 갱신한다. 사용자별 활성 커플 변경 알림으로 초대 대기 폴링을 제거했다. [Supabase DELETE 문서](https://supabase.com/docs/guides/realtime/postgres-changes#delete-events) · [Realtime 권한 문서](https://supabase.com/docs/guides/realtime/authorization)
- 다른 기기에서 스캔하면 기존 원본을 바꾸면서 외래키로 승인까지 삭제됐다. 화면 저장도 미표시 승인을 삭제하는 별도 경로였다. 새 스캔은 현재 커플의 유효한 승인 원본을 보존하며, 저장은 직접 바꾼 항목에만 적용한다. 비교 승인이 바뀌면 상대는 승인 행 정보 없이 신호를 받아 교집합을 다시 조회한다.
- 같은 계정·커플의 새로고침에서 표시값을 유지하고 계정 변경 시 캐시 경계를 지킨다. 지도 안내를 닫을 수 있으며 사귄 날을 늦출 때는 승인과 스캔 기록에 미치는 영향을 저장 전에 안내한다.
- 정리 실패는 서버 로그에 단계와 메시지를 남기며 계정별 오류에는 대상 ID를 포함한다. 목록 조회는 실제 반환 행 수만큼 다음 페이지로 이동한다.

11번 마이그레이션은 기존 Postgres Changes 발행을 비공개 Broadcast로 전환한다. 적용 시점부터 예전 앱은 변경 사항을 API 재조회로 확인하며, 새 실시간 알림은 이번 변경이 들어간 앱에서 받을 수 있다.
